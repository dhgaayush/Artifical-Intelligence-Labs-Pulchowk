  \item To implement \textbf{Breadth-First Search (BFS)} and analyse its completeness and optimality.
  \item To implement \textbf{Uniform-Cost Search (UCS)} and understand how path cost drives expansion.
  \item To implement \textbf{Depth-First Search (DFS)} and observe its memory efficiency vs.\ non-optimality.
  \item To implement \textbf{Iterative-Deepening DFS (IDDFS)} and appreciate its combination of BFS completeness with DFS memory efficiency.

\section{Theoretical Background}

\subsection{Search Problem Formulation}

A \textbf{search problem} is defined by the following components:

\begin{table}[H]
\centering
\caption{Search Problem Components}
\begin{tabularx}{\textwidth}{@{}lX@{}}
\toprule
\textbf{Component} & \textbf{Description} \\
\midrule
Initial State & The state from which the search begins (e.g., Arad) \\
Actions & Set of actions available from a state (e.g., move to neighbouring city) \\
Transition Model & Describes the result of an action: $\text{Result}(s, a) = s'$ \\
Goal Test & Determines if the goal state has been reached (e.g., Bucharest) \\
Path Cost & A function assigning a numeric cost to each path (e.g., sum of road distances) \\
\bottomrule
\end{tabularx}
\end{table}

\subsection{Uninformed (Blind) Search}

Uninformed search strategies use \textbf{no additional information} about the problem domain beyond the problem definition. They can only distinguish goal from non-goal states and generate successors.

\begin{foplbox}
\textbf{Key Characteristics:}
\begin{itemize}
  \item No heuristic or domain knowledge is used
  \item Systematic exploration of the state space
  \item May be inefficient for large or complex problems
  \item Includes: BFS, UCS, DFS, IDDFS
\end{itemize}
\end{foplbox}

\subsection{Informed (Heuristic) Search}

Informed search strategies use \textbf{problem-specific knowledge} beyond the problem definition to find solutions more efficiently. This knowledge is encoded in a \textbf{heuristic function} $h(n)$ that estimates the cost of the cheapest path from node $n$ to a goal node.

\begin{foplbox}
\textbf{Key Characteristics:}
\begin{itemize}
  \item Uses a heuristic function $h(n)$ to guide search
  \item Typically explores fewer nodes than uninformed search
  \item Quality of search depends on quality of the heuristic
  \item Includes: Greedy Best-First Search, A* Search
\end{itemize}
\end{foplbox}

\subsection{Breadth-First Search (BFS)}

BFS expands the \textbf{shallowest unexpanded node} first, using a \textbf{FIFO queue} (first-in, first-out). It explores all nodes at depth $d$ before any nodes at depth $d+1$.

\begin{foplbox}
\textbf{Properties:}
\begin{itemize}
  \item \textbf{Complete:} Yes (if branching factor is finite)
  \item \textbf{Optimal:} Yes (if all step costs are equal); No (if step costs differ)
  \item \textbf{Time Complexity:} $O(b^d)$ where $b$ = branching factor, $d$ = depth of shallowest goal
  \item \textbf{Space Complexity:} $O(b^d)$ --- must store all nodes at current depth
\end{itemize}
\end{foplbox}

\subsection{Uniform-Cost Search (UCS)}

UCS expands the node with the \textbf{lowest path cost} $g(n)$ first, using a \textbf{priority queue} ordered by cumulative cost. It is BFS generalised to handle varying step costs.

\begin{foplbox}
\textbf{Properties:}
\begin{itemize}
  \item \textbf{Complete:} Yes (if step costs $\geq 0$)
  \item \textbf{Optimal:} Yes (always finds the cheapest path for non-negative costs)
  \item \textbf{Time Complexity:} $O(b^{1+\lfloor C^*/\epsilon \rfloor})$ where $C^*$ is optimal cost, $\epsilon$ is minimum step cost
  \item \textbf{Space Complexity:} $O(b^{1+\lfloor C^*/\epsilon \rfloor})$
\end{itemize}
\end{foplbox}

\subsection{Depth-First Search (DFS)}

DFS expands the \textbf{deepest unexpanded node} first, using a \textbf{LIFO stack} (last-in, first-out). It plunges down a single branch until it reaches a dead end, then backtracks.

\begin{foplbox}
\textbf{Properties:}
\begin{itemize}
  \item \textbf{Complete:} No (may get stuck in infinite branches); Yes in finite spaces with visited tracking
  \item \textbf{Optimal:} No (may find a longer or more expensive path)
  \item \textbf{Time Complexity:} $O(b^m)$ where $m$ = maximum depth of the search tree
  \item \textbf{Space Complexity:} $O(bm)$ --- only stores nodes on current path
\end{itemize}
\end{foplbox}

\subsection{Iterative-Deepening DFS (IDDFS)}

IDDFS repeatedly applies \textbf{depth-limited DFS} with increasing depth limits: 0, 1, 2, 3, \ldots\ It combines the \textbf{completeness of BFS} with the \textbf{memory efficiency of DFS}.

\begin{foplbox}
\textbf{Properties:}
\begin{itemize}
  \item \textbf{Complete:} Yes (like BFS)
  \item \textbf{Optimal:} Yes (if step costs are equal); No (if step costs differ)
  \item \textbf{Time Complexity:} $O(b^d)$ --- same as BFS (redundant work is dominated by deepest level)
  \item \textbf{Space Complexity:} $O(bd)$ --- same as DFS (only stores one branch)
\end{itemize}
\end{foplbox}

\subsection{Greedy Best-First Search}

Greedy Best-First Search expands the node that appears to be \textbf{closest to the goal}, using only the heuristic function $h(n)$ to decide which node to expand next. It uses a priority queue ordered by $h(n)$.

\begin{foplbox}
\textbf{Properties:}
\begin{itemize}
  \item \textbf{Complete:} No (can get stuck in loops); Yes with visited tracking in finite spaces
  \item \textbf{Optimal:} No (greedily minimises $h(n)$, not actual path cost)
  \item \textbf{Time Complexity:} $O(b^m)$ in worst case; often much better with a good heuristic
  \item \textbf{Space Complexity:} $O(b^m)$ in worst case
\end{itemize}
\end{foplbox}

\subsection{A* Search}

A* Search expands the node with the \textbf{lowest evaluation function} $f(n) = g(n) + h(n)$, where $g(n)$ is the actual cost to reach node $n$ and $h(n)$ is the estimated cost from $n$ to the goal. It combines the actual path cost (UCS) with the heuristic estimate (Greedy).

\begin{foplbox}
\textbf{Properties:}
\begin{itemize}
  \item \textbf{Complete:} Yes (if branching factor is finite and $h(n)$ is admissible)
  \item \textbf{Optimal:} Yes (if $h(n)$ is \textbf{admissible} --- never overestimates the true cost)
  \item \textbf{Time Complexity:} Depends on heuristic accuracy; $O(b^d)$ in worst case
  \item \textbf{Space Complexity:} $O(b^d)$ --- stores all generated nodes
\end{itemize}

\textbf{Admissible Heuristic:} $h(n) \leq h^*(n)$ for all $n$, where $h^*(n)$ is the true cheapest cost from $n$ to the goal. The straight-line distance is admissible because it can never exceed the actual road distance.
\end{foplbox}

\section{Program 1 --- Breadth-First Search (BFS)}

\subsection{Problem Statement}
Implement Breadth-First Search on the Romanian Map to find a route from Arad to Bucharest. BFS should find the shortest path in terms of number of hops.

\subsection{Algorithm}
\begin{foplbox}
\begin{enumerate}
  \item Start
  \item Create an empty queue and a visited set
  \item Enqueue the start node with path $= [\text{start}]$; mark as visited
  \item While the queue is not empty:
    \begin{enumerate}
      \item Dequeue the front element $(node, path)$
      \item If $node = goal$, return path
      \item For each unvisited neighbour of $node$ (in sorted order):
        \begin{enumerate}
          \item Mark neighbour as visited
          \item Enqueue $(neighbour, path + [neighbour])$
        \end{enumerate}
    \end{enumerate}
  \item If queue empties without finding goal, return failure
  \item End
\end{enumerate}
\end{foplbox}

\subsection{Python Implementation}
\begin{lstlisting}[style=python, caption={Breadth-First Search}]
def bfs(graph, start, goal):
    visited = set()
    queue = [(start, [start])]
    visited.add(start)
    exploration_order = []

    while queue:
        node, path = queue.pop(0)
        exploration_order.append(node)

        if node == goal:
            return path, exploration_order

        for neighbor in sorted(graph[node].keys()):
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append((neighbor, path + [neighbor]))

    return None, exploration_order
\end{lstlisting}

\subsection{Output}
\begin{lstlisting}[style=output, caption={BFS output}]

============================================================
Path Found: Arad -> Sibiu -> Fagaras -> Bucharest
Path Cost:  450
Hops:       3
Nodes Explored: ['Arad', 'Sibiu', 'Timisoara', 'Zerind',
  'Fagaras', 'Oradea', 'RimnicuVilcea', 'Lugoj', 'Bucharest']
\end{lstlisting}

\subsection{Discussion}
BFS found the path Arad $\rightarrow$ Sibiu $\rightarrow$ Fagaras $\rightarrow$ Bucharest with a cost of 450. This is the shortest path in terms of \textbf{number of hops} (3 hops), but it is \textbf{not the cheapest path}. BFS is optimal only when all step costs are equal; since the Romanian Map has varying road distances, a cheaper 4-hop path exists (cost 418, found by UCS and A*). BFS explored 9 nodes before reaching the goal.

\section{Program 2 --- Uniform-Cost Search (UCS)}

\subsection{Problem Statement}
Implement Uniform-Cost Search on the Romanian Map to find the cheapest route from Arad to Bucharest. UCS should find the optimal (minimum cost) path.

\subsection{Algorithm}
\begin{foplbox}
\begin{enumerate}
  \item Start
  \item Create a priority queue ordered by path cost; initialise with $(0, start, [start])$
  \item Create an empty visited set
  \item While the priority queue is not empty:
    \begin{enumerate}
      \item Pop the node with the lowest cumulative cost $(cost, node, path)$
      \item If $node$ is already visited, skip it
      \item Mark $node$ as visited
      \item If $node = goal$, return path and cost
      \item For each unvisited neighbour of $node$:
        \begin{enumerate}
          \item Calculate new cost $= cost + edge\_cost$
          \item Push $(new\_cost, neighbour, path + [neighbour])$ into the priority queue
        \end{enumerate}
    \end{enumerate}
  \item If priority queue empties without finding goal, return failure
  \item End
\end{enumerate}
\end{foplbox}

\subsection{Python Implementation}
\begin{lstlisting}[style=python, caption={Uniform-Cost Search}]
import heapq

def ucs(graph, start, goal):
    visited = set()
    pq = [(0, start, [start])]
    exploration_order = []

    while pq:
        cost, node, path = heapq.heappop(pq)

        if node in visited:
            continue
        visited.add(node)
        exploration_order.append(node)

        if node == goal:
            return path, cost, exploration_order

        for neighbor, edge_cost in sorted(graph[node].items()):
            if neighbor not in visited:
                heapq.heappush(pq,
                    (cost + edge_cost, neighbor, path + [neighbor]))

    return None, float('inf'), exploration_order
\end{lstlisting}

\subsection{Output}
\begin{lstlisting}[style=output, caption={UCS output}]
============================================================
2. UNIFORM-COST SEARCH (UCS)
============================================================
Path Found: Arad -> Sibiu -> RimnicuVilcea -> Pitesti -> Bucharest
Path Cost:  418
Hops:       4
Nodes Explored: ['Arad', 'Zerind', 'Timisoara', 'Sibiu',
  'Oradea', 'RimnicuVilcea', 'Lugoj', 'Fagaras', 'Mehadia',
  'Pitesti', 'Craiova', 'Drobeta', 'Bucharest']
\end{lstlisting}

\subsection{Discussion}
UCS found the optimal path Arad $\rightarrow$ Sibiu $\rightarrow$ RimnicuVilcea $\rightarrow$ Pitesti $\rightarrow$ Bucharest with a cost of \textbf{418}. This is the cheapest possible route. Unlike BFS which found a shorter-hop but more expensive path (450), UCS always expands the node with the lowest cumulative cost, guaranteeing optimality for non-negative edge costs. UCS explored 13 nodes --- more than BFS --- because it must explore all cheaper partial paths before confirming optimality.

\section{Program 3 --- Depth-First Search (DFS)}

\subsection{Problem Statement}
Implement Depth-First Search (iterative, using a stack) on the Romanian Map to find a route from Arad to Bucharest. DFS should demonstrate its memory-efficient but potentially non-optimal behaviour.

\subsection{Algorithm}
\begin{foplbox}
\begin{enumerate}
  \item Start
  \item Create a stack and push $(start, [start])$
  \item Create an empty visited set
  \item While the stack is not empty:
    \begin{enumerate}
      \item Pop the top element $(node, path)$
      \item If $node$ is already visited, skip it
      \item Mark $node$ as visited
      \item If $node = goal$, return path
      \item For each unvisited neighbour of $node$ (push in reverse sorted order so alphabetically first is explored first):
        \begin{enumerate}
          \item Push $(neighbour, path + [neighbour])$ onto the stack
        \end{enumerate}
    \end{enumerate}
  \item If stack empties without finding goal, return failure
  \item End
\end{enumerate}
\end{foplbox}

\subsection{Python Implementation}
\begin{lstlisting}[style=python, caption={Depth-First Search}]
def dfs(graph, start, goal):
    visited = set()
    stack = [(start, [start])]
    exploration_order = []

    while stack:
        node, path = stack.pop()

        if node in visited:
            continue
        visited.add(node)
        exploration_order.append(node)

        if node == goal:
            return path, exploration_order

        for neighbor in sorted(graph[node].keys(), reverse=True):
            if neighbor not in visited:
                stack.append((neighbor, path + [neighbor]))

    return None, exploration_order
\end{lstlisting}

\subsection{Output}
\begin{lstlisting}[style=output, caption={DFS output}]
============================================================
3. DEPTH-FIRST SEARCH (DFS)
============================================================
Path Found: Arad -> Sibiu -> Fagaras -> Bucharest
Path Cost:  450
Hops:       3
Nodes Explored: ['Arad', 'Sibiu', 'Fagaras', 'Bucharest']
\end{lstlisting}

\subsection{Discussion}
DFS found the path Arad $\rightarrow$ Sibiu $\rightarrow$ Fagaras $\rightarrow$ Bucharest with a cost of 450. While it happened to find the goal quickly (only 4 nodes explored), this is \textbf{not the optimal path}. DFS's path depends entirely on the order in which neighbours are pushed onto the stack --- a different ordering could lead to a completely different (and potentially much longer or more expensive) path. DFS is memory-efficient ($O(bm)$) but provides \textbf{no guarantee of optimality}.

\section{Program 4 --- Iterative-Deepening DFS (IDDFS)}

\subsection{Problem Statement}
Implement Iterative-Deepening DFS on the Romanian Map. IDDFS should combine the completeness of BFS with the memory efficiency of DFS by repeatedly applying depth-limited DFS with increasing depth limits.

\subsection{Algorithm}
\begin{foplbox}
\begin{enumerate}
  \item Start
  \item Set $depth = 0$
  \item Repeat:
    \begin{enumerate}
      \item Perform Depth-Limited Search (DLS) from start with current $depth$
      \item If goal found at this depth, return path
      \item Increment $depth = depth + 1$
      \item If $depth > max\_depth$, return failure
    \end{enumerate}
  \item End

  \textbf{Depth-Limited Search (DLS):}
  \begin{enumerate}
    \item If $depth = 0$ and $node = goal$, return success
    \item If $depth > 0$:
      \begin{enumerate}
        \item For each unvisited neighbour:
          \begin{enumerate}
            \item Recursively call DLS with $depth - 1$
            \item If found, propagate success back up
          \end{enumerate}
        \item Backtrack: remove neighbour from visited
      \end{enumerate}
    \item Return failure
  \end{enumerate}
\end{enumerate}
\end{foplbox}

\subsection{Python Implementation}
\begin{lstlisting}[style=python, caption={Iterative-Deepening DFS}]
def dls(graph, node, goal, depth, visited, path):
    if depth == 0 and node == goal:
        return True, path
    if depth > 0:
        for neighbor in sorted(graph[node].keys()):
            if neighbor not in visited:
                visited.add(neighbor)
                found, result = dls(graph, neighbor, goal,
                    depth - 1, visited, path + [neighbor])
                if found:
                    return True, result
                visited.discard(neighbor)
    return False, None

def iddfs(graph, start, goal, max_depth=20):
    exploration_order = []
    for depth in range(max_depth + 1):
        visited = {start}
        found, path = dls(graph, start, goal, depth,
                          visited, [start])
        exploration_order.append(
            f"Depth {depth}: visited {sorted(visited)}")
        if found:
            return path, depth, exploration_order
    return None, -1, exploration_order
\end{lstlisting}

\subsection{Output}
\begin{lstlisting}[style=output, caption={IDDFS output}]
============================================================
4. ITERATIVE-DEEPENING DFS (IDDFS)
============================================================
Path Found: Arad -> Sibiu -> Fagaras -> Bucharest
Path Cost:  450
Hops:       3
Found at Depth: 3
Depth-by-depth exploration:
  Depth 0: visited ['Arad']
  Depth 1: visited ['Arad']
  Depth 2: visited ['Arad']
  Depth 3: visited ['Arad', 'Bucharest', 'Fagaras', 'Sibiu']
\end{lstlisting}

\subsection{Discussion}
IDDFS found the path Arad $\rightarrow$ Sibiu $\rightarrow$ Fagaras $\rightarrow$ Bucharest at depth 3 with a cost of 450. Like BFS, it finds the shortest-depth path (3 hops) but \textbf{not the cheapest path}. The depth-by-depth trace shows that depths 0, 1, and 2 could not reach Bucharest --- the goal was only found at depth 3. IDDFS's key advantage is its \textbf{linear space complexity} $O(bd)$, making it the preferred uninformed search method when memory is limited. The apparent redundancy of re-exploring shallower depths is acceptable because the number of nodes at the deepest level dominates.

\section{Program 5 --- Greedy Best-First Search}

\subsection{Problem Statement}
Implement Greedy Best-First Search on the Romanian Map using the straight-line distance to Bucharest as the heuristic. It should expand the node that appears closest to the goal at each step.

\subsection{Algorithm}
\begin{foplbox}
\begin{enumerate}
  \item Start
  \item Create a priority queue ordered by $h(n)$; initialise with $(h(\text{start}), start, [start])$
  \item Create an empty visited set
  \item While the priority queue is not empty:
    \begin{enumerate}
      \item Pop the node with the smallest $h(n)$: $(h, node, path)$
      \item If $node$ is already visited, skip it
      \item Mark $node$ as visited
      \item If $node = goal$, return path
      \item For each unvisited neighbour of $node$:
        \begin{enumerate}
          \item Push $(h(neighbour), neighbour, path + [neighbour])$ into the priority queue
        \end{enumerate}
    \end{enumerate}
  \item If priority queue empties without finding goal, return failure
  \item End
\end{enumerate}
\end{foplbox}

\subsection{Python Implementation}
\begin{lstlisting}[style=python, caption={Greedy Best-First Search}]
import heapq

def greedy_best_first(graph, start, goal, heuristic):
    visited = set()
    pq = [(heuristic[start], start, [start])]
    exploration_order = []

    while pq:
        h, node, path = heapq.heappop(pq)

        if node in visited:
            continue
        visited.add(node)
        exploration_order.append(node)

        if node == goal:
            cost = sum(graph[path[i]][path[i+1]]
                       for i in range(len(path) - 1))
            return path, cost, exploration_order

        for neighbor in sorted(graph[node].keys()):
            if neighbor not in visited:
                heapq.heappush(pq,
                    (heuristic[neighbor], neighbor,
                     path + [neighbor]))

    return None, float('inf'), exploration_order
\end{lstlisting}

\section{Program 6 --- A* Search}

\subsection{Problem Statement}
Implement A* Search on the Romanian Map using $f(n) = g(n) + h(n)$, where $g(n)$ is the actual path cost and $h(n)$ is the straight-line distance heuristic. A* should find the optimal (cheapest) path.

\subsection{Algorithm}
\begin{foplbox}
\begin{enumerate}
  \item Start
  \item Create a priority queue ordered by $f(n) = g(n) + h(n)$; initialise with $(h(\text{start}), 0, start, [start])$
  \item Create an empty visited set
  \item While the priority queue is not empty:
    \begin{enumerate}
      \item Pop the node with the smallest $f(n)$: $(f, g, node, path)$
      \item If $node$ is already visited, skip it
      \item Mark $node$ as visited
      \item If $node = goal$, return path and cost $g$
      \item For each unvisited neighbour of $node$:
        \begin{enumerate}
          \item Calculate $g' = g + edge\_cost$
          \item Calculate $f' = g' + h(neighbour)$
          \item Push $(f', g', neighbour, path + [neighbour])$ into the priority queue
        \end{enumerate}
    \end{enumerate}
  \item If priority queue empties without finding goal, return failure
  \item End
\end{enumerate}
\end{foplbox}

\subsection{Python Implementation}
\begin{lstlisting}[style=python, caption={A* Search}]
import heapq

def a_star(graph, start, goal, heuristic):
    visited = set()
    pq = [(heuristic[start], 0, start, [start])]
    exploration_order = []

    while pq:
        f, g, node, path = heapq.heappop(pq)

        if node in visited:
            continue
        visited.add(node)
        exploration_order.append(node)

        if node == goal:
            return path, g, exploration_order

        for neighbor, edge_cost in sorted(graph[node].items()):
            if neighbor not in visited:
                new_g = g + edge_cost
                new_f = new_g + heuristic[neighbor]
                heapq.heappush(pq,
                    (new_f, new_g, neighbor, path + [neighbor]))

    return None, float('inf'), exploration_order
\end{lstlisting}

A* found the optimal path Arad $\rightarrow$ Sibiu $\rightarrow$ RimnicuVilcea $\rightarrow$ Pitesti $\rightarrow$ Bucharest with a cost of \textbf{418}. \section{Conclusion}

This lab demonstrated the implementation and comparison of six fundamental search strategies in Artificial Intelligence on the Romanian Map problem:

\begin{enumerate}
  \item \textbf{Breadth-First Search (BFS)} finds the shortest-hop path but is not cost-optimal when step costs vary. It requires significant memory ($O(b^d)$) as all nodes at each depth level must be stored.

  \item \textbf{Uniform-Cost Search (UCS)} guarantees the cheapest path for non-negative edge costs by always expanding the lowest-cost node. It is optimal but may explore many nodes without heuristic guidance.

  \item \textbf{Depth-First Search (DFS)} is memory-efficient ($O(bm)$) but neither complete nor optimal. Its results depend on the order of neighbour exploration.

  \item \textbf{Iterative-Deepening DFS (IDDFS)} combines the completeness of BFS with the memory efficiency of DFS. It finds the shortest-depth path and is the preferred uninformed search when memory is limited.

  \item \textbf{Greedy Best-First Search} uses a heuristic to guide the search towards the goal quickly, exploring very few nodes. However, it sacrifices optimality --- the path found may be more expensive than the optimal route.

  \item \textbf{A* Search} combines the actual cost $g(n)$ with the heuristic $h(n)$ to efficiently find the optimal path. With an admissible heuristic (straight-line distance in our case), A* guarantees optimality while exploring far fewer nodes than UCS.
\end{enumerate}

The Romanian Map problem clearly illustrates that \textbf{informed search (A*)} provides the best trade-off between efficiency and optimality when a good heuristic is available, while \textbf{uninformed search (UCS)} guarantees optimality at the cost of exploring more nodes. The choice of search strategy depends on the problem characteristics, available heuristic information, and the relative importance of optimality versus computational efficiency.
